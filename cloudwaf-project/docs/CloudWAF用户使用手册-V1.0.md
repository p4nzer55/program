## 1. 产品概述

### 1.1 产品简介

CloudWAF是一款基于云架构的Web应用防火墙系统，提供全面的Web安全防护能力。系统采用反向代理架构，支持防护/检测/转发三种模式，能够有效防御SQL注入、XSS、命令注入、CC攻击、扫描行为等多种安全威胁。

### 1.2 核心功能

| 功能模块 | 功能描述 |
|---------|---------|
| **Web攻击防护** | SQL注入、XSS、命令注入、目录遍历等30+条防护规则 |
| **CC攻击防护** | 基于IP的请求频率限制，自动识别并封禁攻击源 |
| **防扫描保护** | 检测404爆破等扫描行为，自动加入黑名单 |
| **访问控制** | IP黑白名单、CIDR格式支持、区域访问控制 |
| **URL级策略** | 针对特定URL路径配置细粒度防护规则 |
| **端口管理** | 精确控制允许访问的端口，未配置端口返回422错误 |
| **维护模式** | 一键关停站点，显示维护页面 |
| **防护报告** | 生成日报/周报/月报/年报，支持多格式导出 |

### 1.3 三种防护模式

```
┌─────────────────────────────────────────────────────────┐
│                    防护模式说明                           │
├─────────────┬───────────────────────────────────────────┤
│  防护模式    │ 检测到攻击后拦截请求 + 记录日志               │
│  检测模式    │ 只记录日志，不拦截请求                       │
│  转发模式    │ 直接转发到后端，不做任何检测                   │
└─────────────┴───────────────────────────────────────────┘
```

## 2. 快速开始

### 2.1 系统部署

#### 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows/Linux/macOS |
| Python版本 | Python 3.7+ |
| 依赖包 | Flask, Flask-SQLAlchemy, requests |

#### 启动服务

```bash
# 进入项目目录
cd cloudwaf

# 启动服务
python app.py
```

#### 验证部署

```
WAF代理入口:  http://localhost:5000
管理后台:     http://localhost:5000/admin
默认账号:     admin / admin123
```

### 2.2 快速接入站点

1. 登录管理后台：http://localhost:5000/admin
2. 进入「站点管理」页面
3. 点击「添加站点」，填写以下信息：
   - 站点名称：自定义（如：公司官网）
   - 站点域名：实际域名或localhost
   - 后端地址：源站服务地址（如：http://httpbin.org）
   - 防护模式：选择「防护模式」
4. 点击「保存」完成接入

### 2.3 测试防护效果

```bash
# 测试SQL注入拦截
curl "http://localhost:5000/?id=1' OR '1'='1"

# 测试XSS拦截
curl "http://localhost:5000/?q=<script>alert(1)</script>"

# 查看拦截日志
# 进入「攻击日志」页面查看拦截记录
```

## 3. 站点管理

### 3.1 添加站点

**步骤：**

1. 点击左侧导航「站点管理」
2. 点击「添加站点」按钮
3. 填写站点信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| 站点名称 | 站点的显示名称 | 公司官网 |
| 站点域名 | 站点访问域名 | www.example.com |
| 后端地址 | 源站服务地址 | http://192.168.1.100:80 |
| 防护模式 | 选择防护模式 | 防护模式 |
| 站点状态 | 启用/禁用站点 | 启用 |

4. 点击「保存」

### 3.2 修改防护模式

**适用场景：**
- 业务上线前先使用「检测模式」观察
- 确认无误后切换到「防护模式」
- 源站故障时临时切换到「转发模式」

**操作步骤：**
1. 在站点列表找到目标站点
2. 点击「修改」或「防护模式」下拉框
3. 选择新的模式：防护/检测/转发
4. 点击「保存」

### 3.3 一键关停（维护模式）

**功能说明：**
开启维护模式后，所有访问请求将返回503维护页面，用于站点升级维护或紧急处理。

**操作步骤：**
1. 在站点列表找到目标站点
2. 点击「维护模式」开关
3. 填写维护提示信息（可选）
4. 点击「确认」

**维护页面效果：**
```
┌─────────────────────────────────────┐
│           🔧 站点维护中             │
├─────────────────────────────────────┤
│  系统正在维护升级中，请稍后再访问     │
│  如有疑问，请联系站点管理员          │
│                                     │
│  CloudWAF 安全防护系统 - 维护模式    │
└─────────────────────────────────────┘
```

### 3.4 回源/回切功能

**功能说明：**
- **回源**：通过DNS修改，流量直接绕过WAF到源站
- **回切**：通过DNS修改，流量重新走WAF防护

**适用场景：**
- 源站故障排查时临时回源
- 验证WAF是否误拦截时使用

## 5. 访问控制

### 5.1 IP黑名单

#### 5.1.1 添加黑名单

**功能说明：**
将指定IP或IP段加入黑名单，拦截所有来自该IP的请求。

**支持格式：**
- 单IP：`192.168.1.100`
- IP段（CIDR）：`192.168.1.0/24`

**操作步骤：**
1. 点击左侧导航「访问控制」
2. 选择「黑名单」标签
3. 点击「添加IP」
4. 填写信息：
   - IP地址：输入IP或CIDR格式
   - 封禁原因：填写原因（可选）
   - 封禁时长：填写秒数（可选，留空表示永久）
5. 点击「保存」

#### 5.1.2 查看黑名单

黑名单列表显示：
- IP地址
- 是否为CIDR格式
- 封禁原因
- 过期时间
- 添加时间

### 5.2 IP白名单

#### 5.2.1 添加白名单

**功能说明：**
白名单中的IP将绕过所有防护检查，直接放行。

**适用场景：**
- 运维人员办公IP
- 管理后台访问IP
- 安全扫描设备IP

**操作步骤：**
1. 点击左侧导航「访问控制」
2. 选择「白名单」标签
3. 点击「添加IP」
4. 填写信息：
   - IP地址：输入IP或CIDR格式
   - 备注说明：填写备注（可选）
5. 点击「保存」

### 5.3 区域访问控制

#### 5.3.1 功能说明

根据IP归属地进行访问控制，支持：
- **白名单模式**：只允许指定国家/地区访问
- **黑名单模式**：禁止指定国家/地区访问

#### 5.3.2 国家代码

| 代码 | 国家/地区 | 代码 | 国家/地区 |
|------|----------|------|----------|
| CN | 中国大陆 | HK | 中国香港 |
| US | 美国 | UK | 英国 |
| JP | 日本 | KR | 韩国 |
| RU | 俄罗斯 | DE | 德国 |
| FR | 法国 | SG | 新加坡 |

#### 5.3.3 配置区域黑名单

**操作步骤：**
1. 进入站点管理，选择目标站点
2. 找到「区域访问控制」模块
3. 点击「添加规则」
4. 填写信息：
   - 规则类型：选择「黑名单」
   - 国家代码：输入国家代码，多个用逗号分隔（如：US,UK,JP）
5. 点击「保存」

#### 5.3.4 配置区域白名单

**操作步骤：**
1. 进入站点管理，选择目标站点
2. 找到「区域访问控制」模块
3. 点击「添加规则」
4. 填写信息：
   - 规则类型：选择「白名单」
   - 国家代码：输入国家代码（如：CN）
5. 点击「保存」

**注意事项：**
- 白名单优先级高于黑名单
- 同时配置时，只允许白名单中的国家访问

### 5.4 查询IP归属地

**操作步骤：**
1. 进入「访问控制」页面
2. 找到「IP归属地查询」模块
3. 输入IP地址
4. 点击「查询」

## 7. 高级功能

### 7.1 URL级防护策略

#### 7.1.1 功能说明

针对特定URL路径配置独立的防护规则，实现细粒度的安全控制。

**应用场景：**
- `/admin/*` 路径启用更严格的防护
- `/api/*` 路径关闭特定规则
- 不同路径配置不同的CC防护参数

#### 7.1.2 添加URL规则

**操作步骤：**
1. 进入站点管理，选择目标站点
2. 找到「URL级策略」模块
3. 点击「添加规则」
4. 填写信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| URL路径 | 正则表达式匹配路径 | `^/admin/.*` |
| 规则分类 | 启用的规则分类 | sql_injection,xss |
| CC防护 | 是否启用CC防护 | 是 |
| 速率阈值 | 每分钟允许请求数 | 30 |
| 覆盖站点规则 | 是否覆盖站点配置 | 是 |

5. 点击「保存」

#### 7.1.3 规则示例

```
示例1：管理后台严格防护
URL路径: ^/admin/.*
规则分类: sql_injection,xss,command_injection
CC速率: 10次/分钟
覆盖站点规则: 是

示例2：API接口适度防护
URL路径: ^/api/v1/.*
规则分类: sql_injection
CC速率: 100次/分钟
覆盖站点规则: 否
```

## 9. 常见问题

### 9.1 防护相关

#### Q1：正常请求被拦截了怎么办？

**A：** 可能原因和解决方法：

1. **触发防护规则**
   - 进入「攻击日志」查看拦截原因
   - 确认是否为误拦截
   - 如确认误拦截，可禁用对应规则

2. **IP被加入黑名单**
   - 检查IP是否在黑名单中
   - 从黑名单中移除

3. **触发CC防护**
   - 检查请求频率是否过高
   - 调整CC防护阈值

#### Q2：如何区分真实攻击和误拦截？

**A：**
- 查看日志中的「匹配内容」字段
- 分析请求是否包含恶意特征
- 在「检测模式」下观察一段时间
- 收集日志进行人工分析

#### Q3：防护规则过多会影响性能吗？

**A：**
- 规则引擎采用正则预编译和缓存机制
- 建议只启用必要的规则
- 定期检查并禁用冗余规则

### 9.2 接入相关

#### Q4：接入后访问404错误？

**A：** 检查以下配置：

1. 站点域名配置是否正确
2. 后端地址是否可访问
3. 端口管理是否配置了对应端口
4. 源站防火墙是否放行WAF服务器IP

#### Q5：HTTPS站点如何接入？

**A：**
1. 在端口管理中添加443端口，协议选择https
2. 确保后端地址使用https协议
3. 开启「HTTP→HTTPS跳转」功能

#### Q6：多域名接入同一个站点？

**A：**
- 为每个域名创建独立的站点配置
- 或使用通配符域名配置（需自定义规则匹配）

### 9.3 日志相关

#### Q7：日志存储多久？

**A：**
- 默认永久存储
- 建议定期归档旧日志
- 可通过数据库维护脚本清理过期日志

#### Q8：如何导出大量日志？

**A：**
1. 使用时间范围筛选减少数据量
2. 分批导出
3. 使用API接口进行批量处理

### 9.4 运维相关

#### Q9：如何升级系统？

**A：**
1. 备份数据库文件
2. 拉取最新代码
3. 运行数据库迁移脚本（如有）
4. 重启服务

#### Q10：系统占用资源多少？

**A：**
- 内存：建议至少512MB
- CPU：视流量而定，建议2核以上
- 磁盘：主要占用来自日志，建议预留充足空间
